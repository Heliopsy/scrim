# Tasks

Milestones: M0 proves the hot path (groups 1-3), M1 makes scrim usable for one agent on one
machine (groups 4-9), M2 covers more stores, providers and Kubernetes (groups 10-13), M3 adds large
deployments and the remaining edge modes (groups 14-16).

Release v0.1.0 ships M0 and M1 plus 10.1 to 10.3, 11.1, 11.2, the env and file sources of 11a.5
and 13.2. Everything else stays open for later releases; v1.0.0 is group 16.

## 2. Redaction core

- [x] 2.0 Hash-window prefilter matcher for large sets with Aho-Corasick for small sets (design D13); verify: identical output to the reference matcher on every fixture and at least 500 MB/s single core at 10,000 secrets

- [x] 2.1 Value dictionary with encoded variants (raw, JSON-escaped, base64 std/url at three alignments, hex, URL-encoded) and minimum-length rule; verify: table tests per variant and per edge length
- [x] 2.2 Multi-pattern matcher over raw request bytes with atomic rebuild and swap; verify: concurrent requests during rebuild never block and never miss a value present before and after the swap
- [x] 2.3 Deterministic placeholders with versioned key and rotation; verify: same value gives same bytes across processes; old-key placeholders still resolve after rotation
- [x] 2.4 Independent guard over exact outgoing bytes (separate code from 2.2), repair or withhold; verify: a value the redactor is made to miss is caught by the guard in tests
  - fix: a value inside a longer value broke the longer one in forms only the guard decodes. With LocalStack's `test` credentials and an `sk-test-...` key both redacted, the redactor replaced `test` (raw in the dump's text column, or its hex form inside a wrapped hex line) inside the key's wrapped hex, `xxd` and `hexdump -C` output, and inside a truncation of the key; what was left was no whole value and no half of one, so the guard passed it and 41 of 48 key bytes reached the provider in every awssm matrix cell. The redactor now finds at build which values lie inside others (raw, case ignored, or in hex form either way) and, around a match of such a value whose neighbouring bytes could belong to the longer value's encoding, asks the guard's decoders what they read in the input; a value found overlapping the match and reaching past it is replaced whole (`Variant::Enclosing`). `scrim-redact/tests/nested.rs` sends 18 forms of a key with `test`, a 12-byte inner value, a 12-byte prefix and a run of the key's hex digits nested in it, through both engines, `protect`, `redact` plus the guard as the LLM proxy calls them, and `find_matches`, and decodes the output independently: before the fix wrapped hex, `xxd`, `hexdump -C` and both truncations leaked (or were refused for the prefix), base64, percent, separated units, reversal and base32 did not. The leak gate's proxy (`test/leak/start-proxy.sh`) now redacts `test` next to the seeds. Sets without nested values take the old path (the bench sets are checked to); with `test` nested, single-threaded `protect` on the 1 MB reference bodies costs 13 % (1,000 values) and 19 % (10,000) more than with `test` alone, and 1.8 and 2.1 times when every match borders bytes of a possible encoding. The leak gate against the real proxy with `test` added failed 12 rows before the fix (`hex-wrapped`, `xxd-dump`, `hexdump-canonical` on every API, the awssm matrix failure) and passes after
